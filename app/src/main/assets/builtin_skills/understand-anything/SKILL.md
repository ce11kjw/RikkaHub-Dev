# 快速读懂陌生代码

不要一上来就读文件。**先建骨架，再看细节。**

## 第一步：找入口

问清楚这个项目从哪开始：

- 可执行程序的 `main` 在哪
- Web 项目的路由注册在哪
- 库的公开 API 在哪个文件导出

不知道入口时，看构建配置（`build.gradle`、`package.json`、`Cargo.toml`）里的 main 字段。

## 第二步：摸清目录职责

```
src/
├── api/        对外接口
├── service/    业务逻辑
├── data/       数据访问
├── model/      数据结构
└── ui/         界面
```

**先确认每个目录干什么，再看里面的具体实现。** 目录命名不可靠时，看哪个目录被 import 最多。

## 第三步：跟一条完整路径

挑一个**最简单的功能**，从入口跟到出口：

```
用户点击 → 路由 → 处理函数 → 业务逻辑 → 数据层 → 返回
```

跟完一条，整个项目的数据流就清楚了。比读十个文件有用。

## 第四步：找耦合点

这些地方最容易出问题：

- **全局状态**（单例、全局变量）
- **循环依赖**（A 依赖 B，B 又依赖 A）
- **隐式约定**（同名文件必须配对、字段顺序有意义）
- **时序依赖**（必须先初始化 X 才能用 Y）

## 回答"这个函数被谁调用"

```
1. 全局搜索函数名（不只是定义处）
2. 看接口/抽象类是否有多实现（调用可能走接口）
3. 看反射/依赖注入（字符串形式的调用搜不到）
4. 看测试（测试里怎么调用的，往往最能说明用法）
```

**搜不到不等于没人调用**——可能在别的模块、可能是动态调用。

## 输出什么

读完给一份「一页纸」：

```
项目名：做什么用的
入口：xxx
核心模块：
  - a/ 负责…
  - b/ 负责…
数据流：请求 → … → 响应
需要注意的坑：
  - xxx 有全局状态，改之前要小心
  - yyy 和 zzz 循环依赖
```

**不要复述代码**，要说清「为什么这么组织」。
