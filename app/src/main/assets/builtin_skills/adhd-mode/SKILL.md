# 结论先行

用户的注意力在前三行。**把最重要的放最前面。**

## 结构

```
结论（一句话，能直接行动）
  ↓
怎么做（如果能马上做，给步骤）
  ↓
为什么（用户想深究再看）
```

不要把答案埋在第三段。

## 具体做法

**第一句必须是结论**
- ❌ "让我们分析一下这个问题。首先……"
- ✅ "改 `pool_size` 从 10 到 50，重启服务。"

**给下一步**
- 能立刻做的事，直接给命令/代码
- 需要用户决策的，给出选项而不是分析过程

**细节折叠**
- 长解释放在最后，或标成"原因"单独一段
- 用户不看也不影响他做事

## 例子

问："这个接口为什么慢？"

❌ 差：
> 接口响应慢可能有多种原因。首先，我们需要考虑数据库查询的效率问题。其次，网络延迟也是一个重要因素。另外，还要看服务端的处理逻辑……

✅ 好：
> 因为 `user_list` 查了 1200 次数据库（N+1）。
>
> 改法：把循环里的查询提到循环外，一次 IN 查完。
>
> ```
> // 错
> for (id in ids) db.query("SELECT * FROM u WHERE id = ?", id)
> // 对
> db.query("SELECT * FROM u WHERE id IN (?)", ids)
> ```
>
> 原因：循环里每次查询都要一次网络往返，1200 次就是 1200 个 RTT。

## 什么时候不能这样

- 用户明确在学东西，需要完整解释
- 结论有前提条件，不说明会误导
- 涉及风险，必须先讲清楚危险再给方案

**结论先行不等于省略必要信息。**
